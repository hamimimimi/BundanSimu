作品名：社会分断シミュレーション
製作期間：半年
使用ツール：Unity　/　C＃
作品概要：


１，ゲームの目的：
このゲームの目的はプレイヤーの行動によってゲーム内の社会に対して意見の対立を顕在化し、社会の分断を深めることを目指すゲームです。


２,ゲームの流れ：

ゲーム開始時に様々な問題をもつランダムな国を生成し、プレイヤーは主にSNSアカウントによってそれに対する人々の意見｛肯定的、否定的、中立的｝および関心を操作していき、様々なイベントとともに社会に影響を与える。


３，未完成の部分：

①ゲームの勝利条件（敗北条件）
　現在の勝利条件は専用のポイントをためることのみであるが、今後そのほかの勝利条件を実装予定。敗北条件はゲーム内に規制圧の数値を実装し、一定数たまるごとにデメリットが発生し、一定を超えると敗北するようにする。具体的にはまだ決定していないが、勝利条件ポイントが急激に上昇すると敗北条件ポイントは上がりやすくなる。（逆もしかり）ことを想定しています。　
②見た目や音に関するものほぼすべて。
③自身のアカウントに関して。
　レベルアップ要素。ステータスを伸ばしやすくする（伸びにくくする）レベルアップを実装予定です。具体的には作成時に一つのレベルアップをとり、以後は数回の行動ごとにレベルアップを得る。マイナスのレベルアップも作る（例えば危険度が上がりやすくなる）。これにより作成したアカウントをより特徴的にする。
④レイアウトの問題について：
　ゲームシステム部分の実装を中心に制作しているため、UIやオブジェクトの配置や大きさが未完成です。具体的にはDebateTree（このゲームのスキルツリーのようなもの）は前提の設定やボタンレイアウトが未実装です。
⑤キャラクターシステム
　ゲーム開始時に様々な効果を持つキャラクター（3種類ほど作成予定）を二人選択してゲームを行う。キャラクターについては一つのキャラクターに正と負の二つの側面を持ち、正と負それぞれから一つ組み合わせる予定。
⑥世論の変化システム
　現在は一度の投稿で、単純な計算式で世論（ゲーム内のCountryVariable）が変化していますが、これを常微分方程式を差分化したものでより現実的に変化させようと考えています。数値変化の検証がまだ途中であり、モデルの修正も考えています。詳細は7に書きます。


４，工夫した点：

６,ゲームの作成意図と反省：

作成に至ったきっかけは二つあります。一つは昨今よく聞く社会の分断のテーマでゲームを作れると思ったからです。もう一つはSNSの情報拡散を常微分方程式で表現できると考えたからです。（ただし、未実装）
そのふたつから、国を生成し、情報発信方法を考えて現在の形になりましたが、ゲームとしては作られていない部分が多く、また使わなくなった部分や不慣れな部分も残っています。


７,作成した常微分方程式モデルについて。　以下の3式です。Sは未支持者（中立）、Iは支持者、Rは反対者を表します。b,r,w,x,y,zは定数です。


dS/dt = - bS(t)I(t) - rS(t)R(t) + wI(t) + xR(t)

dI/dt =  bS(t)I(t)  - yI(t) + zR(t) - wI(t)

dR/dt = rS(t)R(t) +yI(t) - zR(t) - xR(t)



未支持者は支持者と反対者にそれぞれ定数ｂとｒで流れていきます。そしてＩとＲの間で意見が反対になるものを表すのがｙとｚの定数です。そしてＩとＲから関心を失うのがそれぞれ定数ｗとｘです。これらの三つの式の和は０となっていて、一定人口の下で動きます。

そしてそれぞれの定数とＳ,Ｉ,Ｒの初期値は投稿したアカウントの持つ数値やそのほかの値によって決めます。

・各定数と初期値S(0),I(0),R(0)の詳細
b:中立→支持への移行する量に関わる。信用率を用いる。
r:中立→反対への移行する量を関わる。危険度を用いる。
w:支持→中立への移行する量を関わる。（CountryVariable全体に対する）支持への飽きを表し、MyAccによらず、DebateLevelによる。高いほど上がる。
x:反対→中立への移行する量を関わる。（CountryVariable全体に対する）反対への飽きを表し、MyAccによらず、DebateLevelによる。高いほど上がる。
y:支持→反対への移行する量を関わる。危険度を用いる。
z:反対→支持への移行する量を関わる。信用率を用いる。
初期値はその投稿に対してどれだけリーチするかを意味する。つまり、現在のCountryVariableの持つYes,No,Neutralの値とCapと拡散力とPost回数によって決める。
つまり、ゲーム序盤のCapの小さいときはほとんどCap全体に届く、しかし終盤は届きづらくなるイメージ。
CountryVariableの持つYes,No,Neutralの値をそれぞれA,B,C、その和をN、拡散力をIとして、post回数をそれぞれa,b,c、その和をnとして
S(0):IN/(I+N){s*c/n + (1-s)C/N}
I(0):IN/(I+N){s*a/n + (1-s)A/N}
R(0):IN/(I+N){s*b/n + (1-s)B/N}
とする。ただしsは0～１でどれだけフィルターが強いかを表す。値は現在のターンの200分の１（ただし１を超えない）
（ただし、ｎが０となるときは第一項を無視する。）
ベースとなるIN/(I+N)はNがIに比べて小さいときにNに近づく（その逆も同じ）。常にNを超えない。
各式の第一項はpost回数による補正、第二項は基本となるCountryVariableを拡散力に合うように縮小したもの。これにより、同種のPostを多くすることで同じ意見を持つ人に届きやすくなる（フィルターバブルの発生）

ゲームは進むほどに世界（＝Cap）が広がる。投稿は拡散力が高いほど影響が出やすい。世界よりも自分がでかいなら世界全体に影響する。そうでなければ世界の一部だけに影響する。一部の切り出し方が問題。
